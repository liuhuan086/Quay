# Contributing to Quay

Thanks for helping improve Quay.

## Before opening a pull request

1. Open an issue first for substantial behavior or architecture changes.
2. Keep changes focused and avoid unrelated formatting churn.
3. Preserve Swift 6 strict-concurrency guarantees and the existing protocol boundaries.
4. Add or update tests for observable behavior changes.
5. Run the full test suite with Xcode's **Product → Test** or the command in the README.

## Pull requests

Describe the user-visible effect, the implementation approach, and how the change was verified. Include screenshots for SwiftUI changes and note any behavior that still requires a real FTP, FTPS, or SFTP server to verify.
